# 王冠高地 · Crown & Highland

一个可直接在浏览器里玩的 **12×12 布阵象棋**。基本规则沿用国际象棋，但开局前双方要先按规则书阵型为每个槽位选择兵种亚型；棋盘上还有河道与高地。

支持三种模式：

- **人机对战**：三档 AI，使用 Web Worker 计算，不阻塞界面。
- **好友对弈**：创建六位房间码，朋友在另一台设备加入；服务端轮询同步。
- **同屏双人**：一台设备，两位棋手各自布阵、轮流走子。

内置规则书提供速查卡、目录跳转和棋子图鉴：悬停或点选棋子即可查看跟随鼠标的移动/攻击范围示意。

> 规则来源：`docs/规则书.pdf`（原桌面文件）及其 Excel 版本，并按最新修正调整。阵型、地形、兵种走法与车变种见下方规则摘要；规则书中未明确的少量交互在界面规则书与本文末尾标为“本作扩展”。

## 快速开始

需要 Node.js 20+（推荐 24）。

```bash
cd crown-highland
npm start
```

打开 <http://localhost:3000>。

局域网好友对弈：让朋友访问 `http://<你的局域网 IP>:3000`，房主创建房间后把六位房间码发给对方。Windows 首次运行若弹出防火墙提示，请允许 Node.js 访问“专用网络”。若跨互联网，需要把 3000 端口映射/部署到可访问的主机（见“在线部署”）。

本地运行无需 `npm install`：本地 Node 服务只使用内置模块。Netlify Function 需要 `@netlify/blobs`，Netlify 构建时会自动安装。

```bash
npm test        # 引擎规则测试
```

## 玩法

### 1. 布阵

进入任意模式后，左侧是固定阵型预览，右侧按组列出 22 个槽位：

- **王**：4 选 1。
- **后 / 车槽（M1、M2，即 d10 / i10）**：必须分别放一个后和一个车；车只能在运输车与攻城车之间选择。
- **车（R1、R2）**：每个车都可以独立选择运输车或攻城车；本作没有普通车。
- **主教**：红衣主教 / 异端主教。
- **骑士**：甲胄骑士 / 游猎骑士。
- **兵**：步兵 / 弓兵 / 枪兵 / 盾兵。

可以“随机阵容”或“推荐配置”。你最近编辑的阵容会保存到浏览器 `localStorage`；同屏双方的阵容分别保存在当前页面状态中。

### 2. 对局

- 点击自己的棋子，再点击带标记的目标格。
- 同一目标格有多种走法时（例如运输车“普通移动”或“运载”），会弹出行动菜单；运输车有多个正交相邻的兵时，会分别列出每个可携带单位。
- 右侧显示回合、将军、双方子力、被吃子、走子记录。
- 王的能力在选中王后出现在侧栏：大卫王“神佑”可点击发动；查理曼的疾行、亚历山大的再行动由走法本身触发。
- “翻转棋盘”只改变视角，不改变坐标与规则。
- “认输”在在线模式中只认输你执的一方；人机模式中始终是你认输。

### 棋谱记号

行棋记录使用英文棋子缩写：**大写字母为棋子类型，小写字母为亚类**。例如大卫王 `Kd`，甲胄骑士 `Knca`，步兵 `Pin`，弓兵 `Par`，运输车 `Rtr`，攻城车 `Rsg`。

- 普通移动：`Kd e11-e10`；吃子：`Kd e11xe10`。
- 将军：`+`；将死：`#`。
- 远程攻击：`Par a6xb4 (R)`。
- 运输车运载：`Rtr a12-a11 (Pin drop a10)`。
- 升变：`Pin a2-a1=Q`。

### 3. 在线房间

- 房主执白，挑战者执黑，白方先行。
- 房主创建后等待；挑战者输入房间码并配置黑方阵容，加入即开局。
- 双方阵容在开局后公开；落子、认输、大卫神佑、再来一局都通过服务端校验。
- 再来一局需要双方各点一次“请求再来一局”。

## 规则摘要

### 棋盘

- 12×12，坐标 `a`–`l`、`1`–`12`。
- 白方主体在下方第 10–12 行，黑方在上方第 1–4 行，白方先行。
- 白方 e9 / h9 各有一枚前哨兵，黑方镜像为 e4 / h4。
- 双方各 22 枚棋子，阵型固定；玩家只选择亚型与车的变种。

### 地形

| 地形 | 效果 |
| --- | --- |
| 平地 | 普通格。 |
| 河道 | 任何单位不能进入或停留；移动与滑行攻击的路径被河道阻断。弓兵的远程攻击可以跨越河道，但棋子仍会阻挡 L 形射界的前方一格/拐角格。 |
| 高地 | 八方向相连的高地算一整片连续高地；同一片高地内部按平地移动和攻击。进入或离开高地多算 1 格；一次移动不能先上高地再下来。 |

高地会阻挡滑行路径（后、车、主教），但不阻挡弓兵这类不需要抵达目标的远程攻击；骑士的 L 形跳跃可以越过高地。甲胄骑士的正交 1 格不能上下高地；游猎骑士的额外正交移动上下高地只走 1 格，连续高地上可正常走 2 格。普通棋子攻击高地目标时，必须位于山脚相邻格或同一片高地上；攻城车可以沿直线从远处攻击高地。地形按规则书 Excel 逐格还原，地图 180° 对称。

### 胜负

- 吃掉对方王立即获胜（擒王）。
- 将死：对方王被将军且无合法应手。
- 将军：轮到一方时，若对方存在一步可以攻击王，即构成将军；判定按实际攻击路径，河道与高地按各自阻挡规则处理。
- 逼和：轮到一方行棋但无合法走法，且王未被将军。
- 三次重复：同一局面出现三次（包括循环走子或连续将军造成的重复），判和。
- 认输；双方同意和棋（引擎支持，界面暂未提供在线“提议和棋”按钮）。

没有王车易位、吃过路兵。兵到达对方底线时升变，可选择后、运输车、攻城车、红衣主教、异端主教、甲胄骑士或游猎骑士；升变到主教/骑士/车时同时选择具体亚型。

### 棋子与亚型

| 棋子 | 走法 / 攻击 |
| --- | --- |
| 王 | 相邻 1 格直线或斜线；不可主动走入被攻击格。 |
| 后 | 直线/斜线任意格。 |
| 运输车 | 走法/攻击同普通车；只能携带正交相邻的兵（步兵/弓兵/枪兵/盾兵），并沿正交方向把兵送上高地；运输车也可以走到乘客原格。 |
| 攻城车 | 走法/攻击同普通车；可穿过一整片连续高地并落在最后一块高地后一格；停在空高地上时可拆高地。 |
| 红衣主教 | 斜线任意格；额外横向 2 格，仅移动、不能吃子；可利用额外移动上相邻高地。 |
| 异端主教 | 斜线任意格；额外纵向 2 格，仅移动、不能吃子；可利用额外移动上相邻高地。 |
| 甲胄骑士 | 4 个正交 1 格 + 8 个 `(2,1)/(1,2)` 跳跃；L 形跳跃可越过高地，正交 1 格不能从高地出发或落到高地。 |
| 游猎骑士 | 8 个 L 形跳跃；额外正交 2 格，仅移动、不能吃子；上下高地只走 1 格，连续高地上可正常走 2 格。 |
| 步兵 | 永久可走 1 或 2 格；斜前 1 格吃子并占据目标格；可上相邻空高地，可攻击同一片高地上的敌子，但不能从低处攻击高地；下高地只能走正前方 1 格，且在高地上不能攻击高地下的敌人。 |
| 弓兵 | 向前 1 格；初次行动可走 2 格并上相邻高地；左右 1、前方 2 的 L 形点位远程攻击且不移动，路径不受高地阻挡；在高地上只能攻击斜前方 1 格的高地下敌人，不能攻击同一片高地上的斜前方敌人，也不能攻击正前方的高地下敌人。 |
| 枪兵 | 向前 1 格；初次可上相邻高地；斜前 1 格、正前 2 格攻击并占据目标格；正前 2 格可攻击相邻高地；从高地往下时高地边缘占一格，只能攻击正前方 1 格的高地下目标。 |
| 盾兵 | 向前 1 格；初次可上相邻高地；斜前 1 格、正后 1 格攻击并占据目标格；在高地上不能攻击高地下的敌人。 |

### 王的亚型

| 王 | 能力 |
| --- | --- |
| 大卫王 | **神佑**：每局一次。激活后本回合及对手下一回合，王不会被攻击或将军。 |
| 查理曼大帝 | **疾行**：每局一次。王可沿直线/斜线使用 2 点移动力（可借此一步上下高地）。 |
| 亚历山大大帝 | **征服**：王吃子后可以立刻再行动一次；每回合最多一次，再行动只能是王移动，也可跳过。 |
| 凯撒大帝 | **山地统帅**：王上下高地不受额外消耗，也可攻击高地目标。 |

### 特殊交互

- 河道阻挡移动与滑行攻击；弓兵远程攻击可以跨河；棋子阻挡 L 形射界的前方一格/拐角格。
- 高地不阻挡远程视线，但阻挡滑行；骑士的 L 形跳跃可以越过高地。
- 运输车携带的乘客不额外支付地形消耗；乘客和运输车都可以吃掉落点上的敌子。
- 攻城车穿过高地时不会拆高地；只有停在空高地上并选择“拆高地”才会永久移除。
- 本作没有盾兵免疫远程、甲胄骑士免疫兵攻击的设定。

## 本作扩展（规则书未明确）

1. **后 / 车槽**：d10 / i10 必须一后一车。
2. **车的变种**：全场的车（R1、R2 以及后/车槽中的车）只能在运输车与攻城车之间选择，没有普通车。
3. **攻城车**：可穿过一整片连续高地并落在其后一格；可停在空高地上选择拆除或单纯占领。
4. **运输车**：只能携带正交相邻的兵（步兵/弓兵/枪兵/盾兵）；乘客必须与高地正交相邻，运输车沿乘客上高地的同方向移动一格，也可以直接走到乘客原格。
5. **兵升变**：升变可选后、运输车、攻城车、红衣主教、异端主教、甲胄骑士或游猎骑士；升变栏显示在升变棋子的目标格上方，点击选项即确认，不遮挡棋盘；AI 按局面选择。
6. **和棋**：引擎支持协议和棋，但在线界面暂未做“提议/接受”流程；同屏/人机也没有和棋按钮。认输与逼和可用。

### 服务端 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查。 |
| `POST` | `/api/rooms` | 创建房间，body `{ loadout, name? }`。返回 `{ code, token, side, room }`。 |
| `POST` | `/api/rooms/:code/join` | 加入房间，body `{ loadout, name? }`。返回黑方 token。 |
| `POST` | `/api/rooms/:code/loadout` | 等待期间更新阵容（开局后拒绝）。 |
| `GET` | `/api/rooms/:code/state?token=&since=` | 轮询状态；`since` 等于当前版本时返回 `{ unchanged: true }`。 |
| `POST` | `/api/rooms/:code/move` | body `{ token, move }`；服务端用合法走法列表校验。 |
| `POST` | `/api/rooms/:code/action` | body `{ token, action: "david" \| "resign" \| "rematch" }`。 |

本地版房间保存在内存中，8 小时无活动自动清理；Netlify 版保存在 Netlify Blobs，函数重启不会丢房间，读取时按 8 小时 TTL 惰性清理。长期无人访问的旧 key 可能留在 Blobs，可在后台手动删除。

### 在线部署

- 本机/局域网：`npm start`，放行 3000 端口即可。
- 公网：可以部署到任意支持 Node 的主机，设置 `PORT` 环境变量；用反向代理提供 HTTPS 更安全。
- 当前同步是 1.2 秒轮询，不是 WebSocket；对休闲对弈足够，但不适合超快棋。

### Netlify 部署（含好友房）

仓库使用 **Netlify Functions + Netlify Blobs** 保留好友房：

- `/api/*` 由 `netlify/functions/api.mjs` 处理。
- 房间状态保存在名为 `crown-highland-rooms` 的 Blobs store 中，强一致性读写，函数实例之间共享。
- 房间逻辑在 `shared/room-service.js`，本地 `server.js` 和 Netlify Function 共用同一套校验。
- `@netlify/blobs` 已加入 `package.json`，Netlify 构建时会自动安装。

部署步骤：

1. 把项目推到 GitHub。
2. 打开 <https://app.netlify.com/>，选择 **Add new site → Import an existing project**。
3. 选择仓库。Netlify 会读取 `netlify.toml`：
   - Build command：`npm run build:netlify`
   - Publish directory：`dist`
4. 点击 Deploy。首次调用 `/api/*` 时会自动创建 Blobs store，不需要手动配置数据库。
5. 部署完成后访问 Netlify 网址，创建/加入好友房即可。

说明：

- **必须用 Git 导入或 Netlify CLI 部署**，因为 Functions 不会通过手动拖拽 `dist/` 上传。手动拖拽只适合人机/同屏静态版。
- 构建产物 `dist/` 只包含前端和 `/shared/engine.js`；`room-service.js` 只给 Node 函数使用，不会发布到静态目录。
- 在 Netlify 后台的 **Data & Storage → Blobs** 可以看到 `crown-highland-rooms`。
- 1.2 秒轮询会频繁调用 Function；免费额度适合休闲对局，长时间连续对局可把前端轮询间隔调大，或改用 Render 常驻服务。

## 已知限制

- 本地版在线房间为内存存储，服务端重启即失效；Netlify 版存 Netlify Blobs，函数重启不会丢房间。两种版本都没有账号、观战、聊天、断线重连。
- 和棋协议没有在线 UI。
- AI 是普通 alpha-beta + 子力/位置评估，不包含开局库或残局库；高难度在复杂局面可能思考 1–2 秒。
- 棋子使用 Unicode 符号 + 亚型角标，不依赖图片资源；不同系统的字体观感会略有差异。
- 规则书若还有未录入的细节，以 `shared/engine.js` 中的实现和界面规则书为准；欢迎按上面的结构继续补。
